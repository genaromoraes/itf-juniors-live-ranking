# Publicação e coleta de resultados

- Mudanças apenas visuais (layout, textos, cartões, estilos e interações) devem reutilizar os resultados existentes. Nunca iniciar coleta ITF como efeito colateral de uma alteração visual.
- Validar primeiro na prévia. Se o usuário pedir apenas prévia, não enviar ao GitHub nem publicar até autorização.
- Push comum e execução manual padrão publicam sem coleta. O fluxo tenta reutilizar o último pacote completo da mesma semana oficial e valida os dados antes da publicação.
- Se não houver pacote válido, interromper a publicação e explicar o impedimento; não iniciar coleta automaticamente nem publicar dados vazios no lugar dos resultados.
- Coleta nova somente quando solicitada como coleta de dados ou nas rotinas de coleta já agendadas. Para execução manual de coleta, desmarcar use_committed_data. O marcador [fresh-pages] só deve ser usado com autorização de coleta.
- Não alterar horários ou cancelar rotinas de coleta existentes sem solicitação do usuário.
